# 레프글작성 스킬

## 1. 기본 정보
- 스킬 이름: 레프글작성 (RefPost)
- 한 줄 요약: Ref(레프) 사이트의 SEO 기준에 맞춰 글을 작성하거나 기존 글을 점검한다. 사이트는 Next.js 정적 사이트이고 글 하나는 `content/posts/슬러그.json` 하나로 관리된다.
- 카테고리: 콘텐츠 작성 / SEO
- 버전: v2.0

## 2. 호출 방식
- 직접 호출 명령어: /레프글작성
- 자동 인식 키워드
  1. "새 글 써줘" / "글 발행해줘"
  2. "블로그 글 올려줘" / "사이트에 글 추가"
  3. "SEO 점검해줘" / "SEO 기준 맞는지 봐줘"
  4. "타이틀이랑 디스크립션 다듬어줘"
  5. "글자수 확인해줘"
  6. "지식창고에 정리해줘"
- 이 스킬을 쓰면 안 되는 상황
  - 사이트 디자인(app/globals.css)이나 관리자 화면(app/admin) 기능을 고치는 요청
  - 사이트와 무관한 SNS 게시물, 카드뉴스만 만드는 요청

## 3. 입력 파라미터
- 필수 입력값
  - 주제 또는 타깃 키워드 (예: "구글 서치콘솔 등록 방법")
  - 카테고리(분류): seo-content(콘텐츠·SEO) / marketing(마케팅 전략) / project(프로젝트) / automation(자동화 실습) / certificate(자격증) / diary(일기)
    - 메뉴 묶음: 마케팅 지식 = seo-content, marketing (정보성 글) / 포트폴리오 = project, automation, certificate + 소개(/about.html) (내 작업 기록) / 일기 = diary
    - 묶음 판단 기준: 내 경험 없이도 성립하는 개념·방법 글은 마케팅 지식, 내가 직접 한 프로젝트·실습·시험 기록은 포트폴리오
    - 사용자가 "마케팅 지식", "포트폴리오"처럼 묶음 이름만 말하면 그 안의 어느 분류인지 묻는다
- 선택 입력값
  - 슬러그(영문 주소): 기본값은 키워드를 영문 소문자-하이픈으로 옮긴 것
  - 사용자의 경험 메모, 수치, 이미지 파일: 없으면 해당 자리를 [직접 작성]으로 남긴다
  - 공개 설정: 기본값은 기준 충족 시 검색 노출, [직접 작성]이 남아 있으면 작성 중(noindex)
- 우선순위: 사용자가 준 경험·수치 > 이 저장소의 실습 자료 > 일반 지식. 일반 지식으로 사용자 경험을 대신하지 않는다

## 4. 작업 절차

### SEO 기준 (이 스킬의 핵심. lib/site.ts의 RULE 값과 같아야 한다)

| 항목 | 기준 | 측정 방법 |
| --- | --- | --- |
| SEO 타이틀 (title 태그) | 10~15자 | 공백 포함 글자수. 사이트명 접미사는 붙이지 않는다 |
| 메타 디스크립션 | 120~200자 | 공백 포함 글자수 |
| 본문 | 공백 제외 2000자 이상 | 본문(prose) 텍스트만. 요약, FAQ, 관련 글은 제외 |
| 이미지 | 5장 이상 | 본문 안 img 개수. 모두 alt 필수 |
| 소제목 | h2 4개 이상 | 문제 제기 > 개념 > 방법 > 팁 순서 권장 |
| 키워드 | 타이틀 맨 앞, 디스크립션, 첫 문단에 포함, 본문 3회 이상 | 대소문자 무시하고 계산 |
| 내부 링크 | 1개 이상 | 다른 글로 가는 링크 (`/posts/슬러그`, .html 붙이지 않음) |

글 제목(h1)은 타이틀과 따로 둘 수 있다. 타이틀은 검색 결과용으로 짧게, h1은 독자용으로 자연스럽게 쓴다.

### 글 파일 형식 (lib/types.ts의 PostSource가 기준)

글 하나는 `content/posts/슬러그.json` 이다. 파일 이름과 JSON의 `slug` 가 같아야 하고 다르면 빌드가 실패한다. 본문 형식은 둘 중 하나를 고른다.

- HTML 본문 (기본값): `bodyFile` 에 `슬러그.html` 을 적고 `content/posts/슬러그.html` 에 본문(prose 안쪽) HTML을 쓴다. `[직접 작성]` 칸(`<div class="todo">`)과 이미지 자리(`<div class="img-slot">`)를 쓸 수 있다. 관리자 화면에서는 불러올 수 없다
- 마크다운 본문: 사용자가 관리자 화면에서 이어서 고치고 싶다고 하면 `body` 에 관리자 본문 문법(`## 소제목`, `- 목록`, `[글자](슬러그.html)`, `**굵게**`, `[[이미지N]]`)으로 쓰고 `bodyFile` 은 넣지 않는다. todo·img-slot 칸은 쓸 수 없으니 `[직접 작성]` 은 문단으로 남긴다

```json
{
  "slug": "google-search-console-guide",
  "category": "seo-content",
  "keyword": "구글 서치콘솔 등록",
  "seoTitle": "구글 서치콘솔 등록 방법",
  "h1": "구글 서치콘솔 등록 방법: 사이트 소유 확인부터 사이트맵 제출까지",
  "desc": "120~200자 메타 디스크립션",
  "excerpt": "카드에 보일 한두 문장 소개 (없으면 디스크립션을 90자로 줄여 씀)",
  "searchKeywords": "전체 글 검색용 키워드 띄어쓰기로",
  "ldKeywords": "구조화 데이터 keywords, 쉼표로",
  "summary": "핵심 요약 1\n핵심 요약 2\n핵심 요약 3",
  "bodyFile": "google-search-console-guide.html",
  "faqs": [{ "q": "질문", "a": "답변" }],
  "related": ["seo-content-writing-guide"],
  "indexable": false,
  "pubDate": "2026-11-10",
  "modDate": "2026-11-10",
  "images": []
}
```

선택 필드: `breadcrumbTitle`(이동경로 마지막 칸, 기본 seoTitle), `readMinutes`(기본 본문 글자수/500), `related`(기본 같은 분류 우선 2개 자동), `faqSchema: false`(FAQ 답변이 아직 [직접 작성]이면 구조화 데이터를 넣지 않음).

### 단계
- 1단계 주제 분석: 키워드의 검색 의도(정보형, 방법형, 비교형, 후기형)를 정하고 소제목 4개 이상의 개요를 잡는다
- 2단계 타이틀·디스크립션: 타이틀 후보 3개를 만들고 코드로 글자수를 센 뒤 10~15자인 것 중 키워드가 맨 앞인 것을 고른다. 디스크립션도 코드로 120~200자를 확인한다
- 3단계 본문 작성: 위 형식으로 `content/posts/슬러그.json` 과 본문을 만든다. 문단은 3~5문장, 전문 용어는 괄호로 쉬운 설명, 실제 상황 예시 1개 이상. h2에는 영문 id를 붙인다(목차용). 사용자 경험이 필요한 곳은 `<div class="todo">[직접 작성] ...</div>`로 남긴다
- 4단계 이미지: 사용자가 준 이미지는 `public/assets/img/posts/슬러그-번호.확장자`로 저장하고 본문에서는 `/assets/img/posts/...` 로 쓰며 width, height, alt를 넣는다. 이미지가 없으면 넣을 위치마다 `<div class="img-slot">[이미지: 설명, alt 예시]</div>`를 5개 이상 표시한다
- 5단계 구조화 데이터: BlogPosting, BreadcrumbList, FAQPage는 글 페이지(app/posts/[slug]/page.tsx)가 JSON 값으로 자동 생성한다. 화면 FAQ와 구조화 데이터는 같은 `faqs` 값에서 나오므로 따로 맞출 필요가 없다
- 6단계 사이트 갱신: 하지 않는다. 전체 글 목록, 홈 최근 글(최대 6개)과 분류별 글 개수, 분류 페이지, sitemap.xml, rss.xml은 빌드할 때 글 JSON에서 자동 생성된다. 검색 노출 여부는 `indexable` 하나로 정한다
- 7단계 관련 글: 같은 분류 글 2개 정도를 `related` 에 넣는다. 기존 글이 `related` 를 지정하고 있고 새 글이 더 잘 맞으면 그 글의 `related` 에도 새 글을 추가한다 (지정하지 않은 글은 자동 계산되므로 손대지 않는다)
- 8단계 빌드 확인: Node.js가 있으면 `npm run build` 를 실행해 오류가 없는지 확인한다. Node.js가 없으면 실행하지 못했다고 보고한다
- 애매할 때: 카테고리가 넷 중 어디에도 맞지 않으면 새 카테고리를 만들지 말고 사용자에게 묻는다
- 일기(diary): 개인 기록이므로 SEO 기준 미달을 이유로 내용을 부풀리거나 지어내지 않는다. 기준 대비 수치만 보고하고, 검색 노출 여부는 사용자에게 묻는다

## 5. 출력 형식
- 기본 출력: `content/posts/슬러그.json` 과 (HTML 본문이면) `content/posts/슬러그.html`, 이미지가 있으면 `public/assets/img/posts/` 아래 파일. 필요하면 다른 글 JSON의 `related` 수정
- 대화 응답: 바꾼 파일 목록, SEO 기준표 대비 실제 수치, [직접 작성]으로 남긴 위치, 자체 검증 결과
- 점검만 요청받은 경우: 파일은 고치지 않고 기준표 대비 수치와 고칠 문장 제안만 보고한다
- 파일 이름 규칙: 사이트 안 파일은 날짜를 붙이지 않는다. 파일명이 곧 URL이므로 영문 소문자, 숫자, 하이픈만 쓴다

## 6. 품질 체크리스트 (자체 검증)
결과를 내기 전에 아래를 모두 수행하고 결과를 응답 끝에 싣는다. 사용자가 생략하라고 해도 수행하고 보고만 짧게 한다.
- 검증 1 재계산 대조: 타이틀 글자수, 디스크립션 글자수, 본문 공백 제외 글자수, 본문 이미지 수, h2 수, 키워드 횟수를 코드(PowerShell 또는 python -c)로 계산한다. 눈대중 금지
- 검증 2 기준 재대조: 위 수치를 SEO 기준표 숫자와 하나씩 비교해 통과/미달을 표로 보고한다. 미달이면 이유와 보완 방법을 적는다
- 검증 3 산출물 무결성: 글 JSON이 파싱되는지(PowerShell `ConvertFrom-Json`), 파일 이름과 `slug` 가 같은지, `category` 가 6개 분류 중 하나인지, `bodyFile` 이 실제 파일을 가리키는지, 본문의 내부 링크(`/posts/...`)와 이미지 경로(`/assets/...`)가 실제 글·파일을 가리키는지, `related` 슬러그가 모두 존재하는지 확인한다. `npm run build` 를 실행했다면 그 결과와 `out/sitemap.xml`, `out/rss.xml` 에 noindex 글이 없는지도 확인한다
- 그 밖에: 모든 img에 alt가 있는가, 타이틀 맨 앞에 키워드가 있는가, 지어낸 경험·수치가 없는가

## 7. 예외 처리 규칙
- 입력 정보가 부족할 때: 주제와 카테고리가 없으면 묻는다. 경험·수치가 없으면 추정하지 않고 [직접 작성]으로 표시한다
- 데이터에 없는 내용: 시험 기준, 가격, 일정처럼 바뀌는 외부 정보는 공식 출처 확인 문장을 붙이고, 확인하지 못한 수치는 쓰지 않는다
- 기준과 요청이 충돌할 때: 사용자가 더 긴 타이틀을 원해도 기준(10~15자)을 우선 적용하고 이유를 짧게 안내한다. 긴 표현은 h1에 쓴다
- [직접 작성]이 남은 글: `indexable` 을 `false` 로 둔다. noindex가 붙고 sitemap.xml, rss.xml에서 자동으로 빠진다
- 관리자 화면에서 만든 글(JSON에 `body` 가 있는 글)은 JSON 하나가 원본이다. 고칠 때는 `body` 마크다운을 직접 고치고 HTML 본문 형식으로 바꾸지 않는다. 관리자 화면에 같은 글이 임시저장돼 있으면 덮어써질 수 있다고 안내한다

## 8. 연계 가능한 다른 스킬
- 블로그드래프트 (마케팅 프로젝트): 초안을 받아 이 스킬의 기준으로 재구성할 수 있다
- 에스엔에스요약 (마케팅 프로젝트): 발행한 글을 SNS 홍보 게시물로 요약할 때 이어서 쓴다
- 관리자 화면(/admin): 사람이 직접 쓸 때는 관리자 화면이 같은 기준(lib/site.ts RULE)으로 실시간 점검한다

## 9. 예시
- 예시 입력 1: "새 글 써줘. 주제는 구글 서치콘솔 등록 방법, 카테고리 seo-content"
  - 예시 출력 1: content/posts/google-search-console-guide.json 과 .html 생성, 타이틀 "구글 서치콘솔 등록 방법"(13자), 디스크립션 140자 안팎, 본문 2000자 이상, 캡처 이미지 자리 5개 이상을 img-slot으로 표시, 이미지가 없어 `indexable: false`(사이트맵·RSS 자동 제외). 바꾼 파일 목록, 빌드 결과, 검증표 보고
- 예시 입력 2: "ADsP 후기 글 SEO 기준 맞는지 점검만 해줘"
  - 예시 출력 2: 파일 수정 없이 타이틀 15자 통과, 디스크립션 142자 통과, 본문 공백 제외 글자수 미달(수치), 이미지 0장 미달 등을 표로 보고하고 채워야 할 [직접 작성] 위치 목록 제시
